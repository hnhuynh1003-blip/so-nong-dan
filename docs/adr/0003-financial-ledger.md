# ADR 0003 — Financial ledger
Status: PROPOSED.

Choose balanced journal behind quick-entry UI, with typed source links, revision, idempotency and atomic posting. Alternative flat cash-only table cannot distinguish profit, receivables and debt; separate disconnected ledgers risk double counting. Event debit/credit lines sum equal, VND integer; enforce cross-row balance on posting and prevent duplicate economic event even with different retry IDs. Posting only confirmed events; staging/estimated observations not fabricated journal entries. Historical unknown payment remains unknown. Correct by compensating event/revision with reason, preserve original and report snapshot.

Sale on credit: receivable/income; collection: cash/receivable; advance: cash/advance liability; applying advance: liability/receivable without duplicate cash. Expense on credit: expense or asset/payable; payment: payable/cash. Borrow/repay principal: liability/cash; interest separate; internal transfer balances accounts; asset purchase capitalized when policy applicable; household expenses separate. Rent cash vs accrual allocation; shared costs once. Chart of accounts, depreciation and allocation policies need owner approval. DB draft debit XOR credit and confirmed journal check are not sufficient to guarantee balance/immutability; CP-002 must implement and test transaction rules, duplicate event semantics and CAL/A05. No posting engine implemented.

R1 supplement: `../12_R1_DOMAIN_CONTRACTS.md` defines asset/loan transactions, explicit cash direction and noncash deposit application, journal subject and reversal links. These are draft shape and event semantics, not executable posting. CP-002 implements balanced transaction invariants; CP-005 handles finance UI/reconciliation. D12 remains OPEN.
