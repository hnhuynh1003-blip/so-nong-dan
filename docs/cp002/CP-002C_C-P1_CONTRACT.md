## Canonicalization SND-JCS-RESTRICTED-1

Restricted RFC 8785-compatible subset (not a general RFC 8785 implementation). Values null, Boolean, scalar-valid Unicode string, dense data array, plain own-enumerable data record. No toJSON/coercion, Unicode normalization, BOM, nonfinite, negative zero, fractional, exponent or signed JSON number form. Only unsigned canonical integer metadata 0..1000000 at explicitly declared paths: root definitionSchemaVersion/policyVersion/snapshotSchemaVersion, nested policy.definitionSchemaVersion/policyVersion, and policy records in a fixture set under policies[index]. Structural path segments are strings for object keys, numbers for actual array indices. Numeric object keys (including escaped equivalent names), nested arrays or additional object levels never inherit metadata permission. Same spelling elsewhere does not authorize numbers. (F01) Schema validators further constrain versions; authoritative numbers are canonical A-P1 integer strings/rational records. Key order JS UTF-16 lexical code units (not locale or UTF-8 order); array order unchanged. JSON escapes follow ECMAScript JSON.stringify for valid strings only. Parser enforces input byte bound, performs fatal UTF-8 decoding with BOM preservation, then rejects a leading U+FEFF before token parsing. A combined malformed UTF-8/BOM payload is INVALID_UTF8; valid UTF-8 with a leading BOM is INVALID_JSON. Within raw token traversal, first error in token order wins; an invalid numeric token before a duplicate key is INVALID_NUMBER. (F02) Recursive descent and single-token string decoding; duplicate decoded keys rejected before value insertion, including escaped aliases. Generic canonical codec validates structure/number paths; policy, fixture, snapshot and B input schemas are separately mandatory. Raw convenience entry points parsePolicyRecord, parseFixtureSet, createSnapshotFromBytes and replaySnapshotBytes compose the bounded parser and applicable schema checks. Raw fixture sets use the 64 MiB envelope; each canonical policy/approval/effectivity record still has its 64 KiB bound. Invalid raw JSON cannot enter via JSON.parse of untrusted input. Prototype pollution names are inert own data, not assignments to Object.prototype. Typed boundary rejects accessors, symbol/nonenumerable fields, sparse arrays, subclass prototypes, proxies (Node util.types.isProxy), cycles; repeated acyclic references serialize by value. Input is pre-materialized typed data, not arbitrary hostile process memory; own-key enumeration of existing objects is unavoidable. Raw input endpoint is bounded before decode. No hostile code/process sandbox or authentication.

Limits: 65536 UTF-8 bytes per policy/approval/effectivity record and definition envelope; 67108864 bytes per snapshot and typed canonical envelope. Root depth=1; every value/container and each object key counts toward 4000000 nodes (key at member depth); depth <=32. Canonical byte budget enforced before emitting each token, including escapes; strings checked for surrogate validity and escaped byte length before stringify; bounded chunk writer (no unbounded token list or dense slot span). Raw byte budget before fatal decode, parser checks depth/node budget during traversal. Raw whitespace counts toward input bound. Full snapshot includes its digest field; body digest reserves exact overhead for added field and two nodes. Digest prefix bytes excluded from envelope byte counts. Codec returns bytes or streaming digest/byte/node metrics; no truncation. Registry set max 1000 total policy+approval+effectivity records, validated before per-record traversal. Each ID same B grammar ASCII [A-Za-z0-9][A-Za-z0-9._:-]* <=128. All limits candidate operation bounds, not history/annual caps. At high B limits combined input+output may exceed snapshot node/byte budget; deterministic RESOURCE_LIMIT, no partial snapshot. Typed API cannot undo allocation already made by caller or accepted bounded B engine. No general streaming DB/import.

Digest: definition = lowercase SHA256(canonical UTF8({definitionSchemaVersion,definition})); exactly these two fields, no prefix. Input = SHA256(UTF8('SND/C-P1/INPUT/v1\\0') || canonical input bytes); result analogous RESULT/v1; snapshot analogous SNAPSHOT/v1 over full body excluding only snapshotSha256. Here \\0 denotes one NUL, not two characters. Snapshot schema 1 and canonicalization version included in body. No display strings or JSONB formatting. New domain hashes FIXTURE/v1 and CHANGE/v1 use UTF-8 `SND/C-P1/FIXTURE/v1\0` and `SND/C-P1/CHANGE/v1\0` respectively over the complete individual canonical record, with the 64 KiB policy bound. Prefix and NUL have exactly the same convention as INPUT/RESULT/SNAPSHOT. The original four digest algorithms, canonicalization version, and snapshot field shapes are unchanged. Trusted external anchors, not hashes derived from untrusted inputs, are required. Hashes are not signatures. All authority remains FIXTURE_ONLY.

## Policy and fixture selection

Policy exact keys `{authority:'FIXTURE_ONLY',ownerId,policyId,policyKey,policyVersion,definitionSchemaVersion,definition,definitionSha256,canonicalizationVersion,sourceRef}`. Versions integers 1..1000000; definitionSchemaVersion exactly 1. Definition exact closed shape B_DEFINITION: profile B-P1 v1.0, ordered steps gross / proportional tare / net / commercial (no impurity) / nearest 1000g tie positive / exact VND, saleScope whole-sheet, price positive integral VND/kg input, no group rerounding. Hash must match; unsupported definition/version/key => UNSUPPORTED_POLICY. Only family rice-sheet-single-price-v1; ratio/price never policy constants. No interpreter. Identity uniqueness per owner+policyId and owner+key+version even identical duplicates. All records copied and frozen; history consistency only within supplied set, no persistent cross-call immutability/authentication.

Fixture set exact `{authority:'FIXTURE_ONLY',policies,approvals,effectivities}`; both input and validated output require/carry fixture-only authority. Approval exact `{authority,ownerId,approvalId,policyId,definitionSha256,scope:'rice-sheet-whole',decisionTime,evidenceRef}`. Effectivity union: INTERVAL `{authority,kind,ownerId,effectivityId,policyId,approvalId,definitionSha256,scope,start,end,evidenceRef}` (end null unbounded); RETIREMENT `{authority,kind,ownerId,effectivityId,policyId,approvalId,definitionSha256,scope,retiredAt,evidenceRef}`. Append-only retirement distinct from original interval; one retirement per owner/policy; no interval begins at/after retirement; intervals of same policy must not overlap in effective time. Approval decisionTime <= start/retiredAt. All times canonical UTC ISO milliseconds YYYY-MM-DDTHH:mm:ss.sssZ, valid roundtrip; separate businessDate YYYY-MM-DD Gregorian, no implicit clock or date inference. Cross-owner policy/approval/hash/scope mismatch reject. `validateFixtureSet(set)` is structural validation only, not proof of authenticity. `evaluateFixture(set,{authority,ownerId,evaluationTime,requestedPolicyId:null|string},trustedContext)` is **as-of fixture simulation only**, with no creation or historical application authority. Request shape/identity/time grammar is validated first; then full registry consistency, independently trusted anchors, then eligibility count at supplied time. More than one eligible interval -> AMBIGUOUS before checking requested ID existence/eligibility. If not ambiguous and explicit ID absent under owner -> REJECTED/UNKNOWN_POLICY; zero eligible with no request or known request -> BLOCKED/NO_ELIGIBLE_POLICY; one eligible and different requested ID -> REJECTED/REQUESTED_POLICY_INELIGIBLE; otherwise ELIGIBLE_FIXTURE. A request cannot select an arbitrary winner. Future or past overlap of different policies is AMBIGUOUS at affected time. Invalid same-policy histories are rejected structurally, independent of requested ID. (F04)

### Independent trusted fixture context (F05/F06)

`TrustedFixtureContext` is a separate input argument, **not** part of caller's calculation request or snapshot. Exact `{authority:'FIXTURE_ONLY',decisionTime:UTC timestamp,records:[{kind:'POLICY'|'APPROVAL'|'EFFECTIVITY',ownerId,recordId,sha256}],changeEvidenceSha256:null|string}`. The 1000-record total bound applies independently to anchor inventory; entries exact shapes, unique `(kind,ownerId,recordId)`, bounded canonical IDs and lowercase SHA-256. `recordId` respectively policyId/approvalId/effectivityId. Digest = FIXTURE/v1 over each full record including source/evidence refs, authority, hash, owner, identity and temporal fields. Inventory represents the complete expected trusted fixture set; no order-dependent inventory digest (records keyed by identity); every supplied record must have a matching independent anchor, and every expected record must be available before selection/VERIFIED. Absent context or omitted expected evidence cannot yield eligibility/VERIFIED. Extra unanchored supplied record or hash mismatch is REJECTED/HASH_MISMATCH in selection, MISMATCH in replay. The context, its decisionTime, anchor inventory and change digest must be supplied by a trusted host independently of the records under verification. C does not manufacture, fetch or authenticate this source; accepting caller replacement of both context and records is outside the supported trust boundary. No production registry, approval signature or identity persistence.

Three modes are separate: evaluateFixture is as-of simulation at explicit supplied time; createSnapshot requires the selected evaluationTime equal trustedContext.decisionTime (otherwise BLOCKED/CREATION_TIME_MISMATCH, subject to earlier invalid/ineligible selection checks), never implicit wall-clock and never backdate a new snapshot by using a historical simulation result. Historical replay validates the snapshot's pinned time (<= supplied trusted decisionTime), independently anchored current historical evidence and exact pinned records; later retirement does not invalidate earlier verified evidence. New trusted inventories may add independently anchored later records. A stale/incomplete or substituted inventory cannot be treated as the original authority. No actual retrospective application.

## Snapshot and engine

`createSnapshot(set,{authority:'FIXTURE_ONLY',input:SheetInput,evaluationTime,businessDate,requestedPolicyId:null|string},trustedContext)` returns deeply frozen exact `{authority,kind:'PREVIEW_EVIDENCE',snapshotSchemaVersion:1,canonicalizationVersion,ownerId,sheetId,revisionId,input,inputSha256,policy,approval,effectivity,evaluationTime,businessDate,engine,result,resultSha256,snapshotSha256}`. The pinned evaluationTime is the explicit trusted creation decisionTime. Source copy preserves original order and raw data; B preview uses accepted static adapter and may sort result. Complete B result includes missing/null/zero/fractions. Strict request; no caller totals or engine injection. Invalid input/selection throws typed CError (or accepted RiceError); no partial result. Snapshot schema/digest domains unchanged from historical draft; draft snapshots are not grandfathered as trusted, and replay always needs independent anchors. `createSnapshotFromBytes(set,requestBytes,trustedContext)` has the same gates after bounded parsing.

`replaySnapshot(snapshot,set,expectedSnapshotSha256,trustedContext)` and `replaySnapshotBytes(bytes,set,expectedSnapshotSha256,trustedContext)` return FIXTURE_ONLY VERIFIED/MISMATCH/UNAVAILABLE. Supplied complete snapshot must have all required nonnull pinned references, input and result. Only truly absent external resource or absent transport (null/undefined API argument) can be unavailable; encoded JSON null is a supplied malformed envelope, not absent transport. Replay checks full body digest plus independently supplied expected snapshot digest, complete input/result digests and schema, identities, pinned policy/approval/effectivity and engine. Expected snapshot digest must come from an independent trusted receipt, not the snapshot being verified. Partial external set is allowed for availability classification only: validate all supplied records and available relations; compare all present pinned references and expected anchor digests before declaring missing evidence. Missing dependency must be expected by trusted inventory, otherwise contradiction. Complete trusted set gets strict registry validation. Present contradictory record, overlap or retirement at pinned time wins before unrelated missing resource. No current eligibility requirement for earlier retired policy. Known B wire shape checked even with unavailable engine; full numeric/domain and exact result validation requires the fixed accepted adapter. If it is available it recomputes and compares entire canonical output even when an unrelated anchor/resource is absent (pure preview, not authority). No fallback or arbitrary archive execution. No VERIFIED with incomplete anchors or evidence. See detailed precedence below (F03/F06/F07/F08/F11). Only single sheet; group snapshots deferred.

Engine binding trust root is compiled C module and trusted fresh Node ESM process using exact Node 22.16.0 and compiler 5.8.3, no module loaders/hooks/cache injection, no concurrent artifact writes, trusted filesystem and host. Accepted B source commit b4f94a3fe24c02be292247184aeaca33b2375a4a and A source commit 80fb95175e902e6bea3caac518a8a6b25b9c1815. Manifest embeds immutable source hashes, compiled relative paths/hashes (B and A plus tiny C static adapter), both lock hashes, toolchain, build/API instructions and accepted oracle digests. Local runner requires separately supplied external expected-source and expected-compiled manifests, each with separately provided expected SHA-256; baseline receipt must match exact accepted parent/tree/A/B and externally retrieved accepted pins, plus historical engine identity digest. It verifies actual C source, accepted source/locks/compiler pins before isolated compile, compares all compiled bytes against the independently supplied expected manifest, and confirms fixed adapter execution. Engineering-local expected C source and separate-build compiled manifest are verification inputs, not an independent verifier verdict; later independent review must anchor the exact candidate commit/tree and manifest outside that candidate. Full checkout and clean npm ci limitations must be disclosed; exact version string alone is insufficient. `engineAvailable()` is artifact/function availability only, never full build attestation. (F10) Adapter statically reexports only accepted B function; engine loads only fixed literal local adapter after byte check (no caller path, callback, arbitrary archive execution); independently resolves B fixed path and checks exported function identity. File bytes rechecked before each invocation; no fallback to latest. Caller-supplied engine manifest cannot define trust root. Validate all supplied engine manifest fields, including nested source/artifact/lock paths and digests, compiler/runtime/package manager, config, build instructions, oracle paths/seeds/vector digests, result digest inventory and both commit identities before availability classification. Relative path grammar, nonempty unique inventories <=1000 entries each, 64 KiB manifest, exact shape and bounded text. Only full exact known identity can execute. Well-formed different source commit -> UNAVAILABLE/ENGINE_UNAVAILABLE; malformed identity or same-source divergent manifest -> MISMATCH. Missing/altered local artifact -> UNAVAILABLE. (F07) In-process filesystem/loader adversary or forged entire trusted program outside supported boundary; immutable production build provenance/signatures deferred. Node-only isolated module not imported by UI.

## Historical observations and correction plans

The A-P1 parser is separately pinned and may validate UNKNOWN observations even if B is unavailable. `historicalUnknown({authority,ownerId,observationId,policy:'UNKNOWN',observedAmount:RationalWire|null,unit:'VND'|'g'|'kg',sourceRef,verificationStatus:'UNVERIFIED'|'VERIFIED'|'DISPUTED'})` validates A-P1 exact value and preserves all supplied fields; no computed amount/cash/debt. `planCorrection(snapshot,set,expectedSnapshotSha256,{authority,newInput,policyChange:null|ChangeEvidence},trustedContext)` requires verified old snapshot and new distinct caller revision, same owner/sheet/group/whole-sheet scope. B computes new preview under original policy/engine without current selection. Returns FIXTURE_ONLY PLANNED_FIXTURE with original snapshot digest, pinned policy/engine and new input/preview; original frozen copy untouched. Unavailable rules, wrong scope/identity -> BLOCKED. ChangeEvidence exact `{authority,purpose:'RULE_CHANGE_PLAN_ONLY',originalSnapshotSha256,ownerId,sheetId,fromRevisionId,toRevisionId,fromPolicyId,fromDefinitionSha256,toPolicyId,toDefinitionSha256,approvalId,decisionTime,evidenceRef}`. Match old anchored snapshot, scope/revisions, original and target policy identities/hashes, trusted target policy/approval, change-specific decision time >= original evaluation and target approval and <= trustedContext.decisionTime. Separately supplied `changeEvidenceSha256` must match CHANGE/v1 canonical hash over the entire evidence record, including provenance and purpose. General target approval and a supplied evidenceRef do not establish change-specific authority. Missing/mismatched change anchor or identity -> BLOCKED/POLICY_CHANGE_APPROVAL_REQUIRED (malformed schema/authority -> typed BLOCKED reason); fully valid separate anchored evidence -> BLOCKED/POLICY_CHANGE_DEFERRED, **never executes target rule**.
